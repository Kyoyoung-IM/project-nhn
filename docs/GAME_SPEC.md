# 게임 명세

이 문서는 NAN 2026 머지 디펜스의 확정 규칙, 임시 데이터, 불일치 및 검증 필요 사항을 관리한다.

## 문서 원칙

- 사용자 답변으로 확정된 규칙에는 확인 날짜를 기록한다.
- 초기 PDF, 시트, 화면 스케치는 참고자료이며 서로 충돌할 경우 임의로 우선순위를 정하지 않는다.
- 미확정 값은 코드와 데이터에서 `TODO`, `PLACEHOLDER` 또는 개발 플래그로 표시한다.
- 밸런스 값은 교체 가능한 데이터로 관리하고 전투 코드에 직접 하드코딩하지 않는다.

## 현재 확정된 방향

- Godot 4와 GDScript를 사용한다.
- 브라우저에서 실행되는 Web 빌드를 목표로 한다.
- Compatibility 렌더러와 단일 스레드 Web 내보내기를 기본으로 한다.
- 적은 고정 수평 경로와 상태 전환을 이용해 층별로 이동한다.
- 제출 빌드는 외부 데이터 서비스 없이 로컬 데이터만으로 동작해야 한다.
- 2026-08-03 확인: 지상층은 몬스터의 지하 진입 연출을 위한 비전투 공간이다.
- 2026-08-03 확인: 실제 전투는 지하 3개 층에서 진행한다.
- 2026-08-03 확인: 적은 지상에서 진입한 뒤 지하 3개 전투층 모두에서 오른쪽에서 왼쪽으로 진행한다.
- 2026-08-03 확인: 각 전투층의 왼쪽 출구에 도달하면 다음 층의 오른쪽 입구로 하강 전환한다.
- 2026-08-03 확인: 몬스터가 가장 깊은 층의 경로 끝에 도달하면 플레이어가 패배한다.
- 2026-08-03 확인: 최심부 코어는 지하 3층의 왼쪽 경로 끝에 배치한다.
- 지상층은 향후 기능 확장을 고려해 전투층과 분리된 구간으로 유지한다.
- 2026-08-03 확인: 각 지하 전투층은 고정 터렛 슬롯 5개를 제공한다.
- 2026-08-03 확인: 각 전투층은 왼쪽 배치 영역 60%와 오른쪽 몬스터 진입 여백 40%로 나누며, 슬롯 5개는 왼쪽 60% 안에만 적당한 간격으로 배치한다.
- 2026-08-04 분기 변경: `agent/indestructible-towers-day-night` 버전의 아군 터렛은 체력과 사망 상태가 없는 고정 불파괴 오브젝트다.
- 2026-08-04 확인: 같은 층의 터렛과 몬스터 간 사거리는 화면 배치의 수직 간격을 제외하고 수평 거리만 비교한다.
- 2026-08-04 분기 변경: 원본 Monster 테이블에 공격 관련 속성이 없으므로 몬스터의 터렛 공격·저지 로직을 사용하지 않는다.
- 2026-08-03 확인: 화면 하단에는 TFT 챔피언 상점 형태의 터렛 구매 UI를 배치한다.
- 2026-08-03 확인: 상점 카드는 기본 상태에서 터렛 이미지·이름·가격을 표시하고, 마우스 호버 시 이름·이미지·효과·상세 능력치를 표시한다.
- 2026-08-03 확인: 골드 표시와 리롤 버튼은 상점에 속한 기능이므로 상점 카드 옆의 전용 제어 영역에 배치한다.
- 2026-08-03 확인: 일반 플레이의 상점 카드는 `ShopGacha` 확률에 따라 실행·초기화·리롤마다 무작위로 추첨한다. 자동 테스트와 디버그 실행은 재현 가능한 고정 시드를 지원한다.
- 2026-08-03 확인: 터렛 구매는 상점 카드에서 빈 슬롯으로 드래그하는 방식으로 진행하며, 유효한 빈 슬롯에 드롭해 설치가 확정된 뒤에만 골드를 차감한다.
- 2026-08-03 확인: 상점 카드를 잘못된 위치나 점유된 슬롯에 놓으면 설치와 골드 차감을 모두 취소한다.
- 2026-08-04 분기 용어 변경: 상점 카드 구매·빈 슬롯 배치·리롤은 낮과 밤 모두 가능하다.
- 2026-08-04 분기 용어 변경: 설치된 터렛의 드래그 위치 이동과 설치 터렛 간 머지는 낮에만 가능하고 밤에는 불가능하다. 상점 카드로 실행하는 구매 머지는 밤에도 가능하다.
- 2026-08-03 확인: 리롤 버튼은 사용 가능 상태를 밝은 강조색으로, 골드 부족 상태를 어두운 회색과 명시적인 부족 문구로 구분한다.
- 2026-08-04 분기 용어 변경: 낮에는 설치된 터렛을 마우스로 드래그해 같은 층의 빈 슬롯으로 이동할 수 있다.
- 2026-08-04 분기 용어 변경: 설치된 터렛은 다른 층으로 드래그 이동할 수 없으며 밤에는 이동할 수 없다.
- 2026-08-04 확인: 낮에 같은 층의 동일 `turretId`·Tier 터렛을 직접 드래그해 겹치면 두 터렛을 `nextTurretId`의 상위 터렛 하나로 머지한다. 동일 터렛이 배치되어 있어도 자동 머지는 하지 않는다.
- 2026-08-04 임시 결정: 층간 머지와 밤 단계의 터렛 이동·머지는 기획 확정 전까지 허용하지 않는다.
- 2026-08-04 확인: 머지 결과의 전투 스탯은 데이터 테이블의 상위 터렛 행을 사용하고, 실제 이미지 에셋 전에는 Tier별 더미 도형과 짧은 승급 이펙트를 사용한다.
- 2026-08-04 확인: 상점 카드를 동일 `turretId`·Tier의 설치 터렛에 드롭하면 낮과 밤 모두 카드 가격을 지불하고 상위 Tier로 머지한다. 호환되지 않는 점유 슬롯에서는 구매와 결제를 취소한다.
- 2026-08-04 확인: 낮에 설치 터렛을 상점 UI 하단 50% 영역으로 드래그해 놓으면 판매하며 밤에는 판매할 수 없다.
- 2026-08-04 확인: 터렛은 실제 투입된 구매가를 누적하고 설치 머지는 양쪽 비용을 합산, 상점 구매 머지는 카드 가격을 추가한다. 판매가는 `floor(누적 구매가 × 0.5)`로 임시 계산한다.
- 2026-08-04 확인: 판매 구역에 진입한 동안 상점 하단에 붉은 그라데이션과 `판매 (판매가)` 안내를 표시한다.
- 2026-08-04 데이터 갱신: `totalWaveCount=4`, `rerollPlusCost=5`, `spawnOrderInterval=0.5`가 기준 테이블의 정식 값으로 제공되어 기존 로컬 보정을 제거했다.
- 2026-08-04 데이터 갱신: `wave3`의 `spawnOrder`가 1~10의 고유 값으로 정리되어 모든 웨이브를 `spawnOrder` 오름차순으로 실행한다.
- 2026-08-04 분기 용어 변경: 게임 시작 전과 각 밤 시작 전에는 `prepareTimeSec` 동안 낮 단계를 둔다.
- 2026-08-04 분기 용어 변경: 리롤 비용은 낮 안에서 실행할 때마다 `rerollPlusCost`만큼 누적 증가하고, 다음 낮에서 기본 비용으로 초기화한다.
- 2026-08-03 확인: 기준 데이터 테이블에 `rerollPlusCost`가 없어 기획 확인 전까지 로컬 프로토타입은 기존 임시값 `5`를 유지한다.
- 2026-08-03 확인: `totalWaveCount=5`이지만 `wave5` 스폰 데이터가 없어 기획 확인 전까지 로컬 프로토타입을 4웨이브로 구성한다.
- 2026-08-03 확인: `wave3`의 중복 `spawnOrder`는 병합하거나 재정렬하지 않고 데이터 테이블 행 순서대로 실행한다.
- 2026-08-03 확인: 자료에는 개체 간 스폰 간격 `monsterSpawnInterval=0.4초`만 있고 서로 다른 Spawn Order 그룹 간격은 없으므로, 기획 확정 전까지 로컬 프로토타입에 `spawnOrderIntervalSec=10초`를 적용한다.
- 2026-08-03 확인: `failAllowedMonster`는 원본 데이터 호환 필드로 보존하지만 현재 패배 판정에는 사용하지 않는다. 패배 조건은 최심부 코어 도달 규칙을 유지한다.
- 2026-08-03 확인: 오브젝트 데이터는 `Define`, `Turret`, `Monster`, `SpawnTable`, `ShopGacha` 구조로 분리한다.
- 2026-08-03 확인: Web 게임 화면은 브라우저 크기 변화에 따라 기준 해상도 `1920×1080`의 비율을 유지하며 자동 확대·축소하고, 남는 축의 가운데에 배치한다.
- 2026-08-03 확인: 플레이 판단에 필요하지 않은 장식 텍스트와 몬스터 진행 방향 화살표는 표시하지 않는다.
- 2026-08-04 확인: 웨이브 진행 중에는 `×1`, `×2`, `×3` 게임 속도를 선택할 수 있으며, 웨이브가 끝나면 기본 속도 `×1`로 초기화한다.
- 2026-08-04 분기 변경: 준비 단계의 표시 명칭은 `낮`, 웨이브 단계의 표시 명칭은 `밤`이며 두 단계 사이에 짧은 색조 전환 연출을 사용한다.

## 불일치 및 검증 필요

- 서로 다른 층 사이의 터렛 머지 허용 여부 (`Design Request/20260804 REQUEST.md`의 `REQ-DESIGN-001`)
- 밤 단계의 설치 터렛 이동·설치 터렛 간 머지 허용 여부 (`Design Request/20260804 REQUEST.md`의 `REQ-DESIGN-002`; 상점 카드 머지는 현재 허용)
- 전체 5웨이브 설정과 4웨이브까지만 존재하는 SpawnTable의 관계
- 4웨이브 보스 4기 설정의 의도 여부
- 상점 카드 4개와 터렛 5종 데이터의 관계
- 기준 데이터 테이블에 없는 터렛 판매 반환 비율의 정식 필드와 값 (`Design Request/20260804 REQUEST.md`의 `REQ-DATA-007`)

- 2026-08-03: 전투층별 고정 터렛 슬롯 5개, 터렛 체력, 하단 카드 상점 UI 확정.

- 2026-08-03: 모든 지하 전투층의 이동 방향을 오른쪽에서 왼쪽으로 통일하고 최심부 코어를 B3 왼쪽 끝으로 이동.

- 2026-08-03: 상점 카드의 기본/호버 정보 구조를 확정하고, 정비 시간 중 같은 층 빈 슬롯으로만 가능한 터렛 드래그 이동 규칙을 확정.
- 2026-08-03: 골드 표시와 누적 비용 리롤 버튼을 상단 HUD에서 하단 상점 전용 제어 영역으로 이동.
- 2026-08-03: 일반 플레이 상점 RNG를 무작위화하고 자동 테스트 및 `--shop-seed=<숫자>` 디버그 시드는 재현 가능하게 유지.
- 2026-08-03: 상점 클릭 후 슬롯 클릭 구매를 상점 카드에서 빈 슬롯으로 드래그하고 유효 드롭 시 결제·설치하는 방식으로 변경.
