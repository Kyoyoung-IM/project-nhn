# 이미지 생성 및 그래픽 작업 지침

이 문서는 생성형 이미지 제작·편집과 게임 규칙 또는 UI 배치 구조를 바꾸지 않는 단순 그래픽 작업에 적용한다.

## 이미지 생성 도구 사용 기준

- 생성형 이미지 도구는 사용자가 새 이미지, 일러스트, 아이콘, 배경, 스프라이트, 리터칭 또는 시안 제작을 명시적으로 요청했거나 요청의 의미상 이미지 제작이 분명한 작업에서만 사용한다.
- 사용자가 정확히 `이미지 생성`이라는 표현을 쓰지 않았더라도 새 비트맵 에셋 제작이 요청의 핵심이면 허용한다.
- 프로젝트 관리, 버그 수정, 데이터 테이블, 일반 문서 작성, 코드 수정과 일반 UI 구현 요청은 이미지 생성 권한을 포함하지 않는다. 설명용 장식 이미지나 임의 시안을 만들기 위해 생성 도구를 선제적으로 사용하지 않는다.
- 일반 UI 작업에 새 비트맵 에셋이 필요하지만 이미지 제작 요청이 명확하지 않으면 기존 승인 에셋이나 Godot 씬·리소스로 구현 가능한 표현을 우선한다.
- 새 이미지가 반드시 필요하면 생성하지 않고 필요한 에셋, 사용 위치와 예상 영향을 보고해 승인을 받는다.
- 사용자가 에셋 종류, 콘셉트와 시안 범위를 한 번 승인하면 그 범위 안의 변형 생성은 다시 승인받지 않는다. 승인 범위를 벗어난 다른 에셋이나 새 콘셉트는 별도 요청이 필요하다.

## 그래픽 전용 브랜치

- 이미지 생성, 기존 이미지 교체, 단순 리터칭, 색상·명암·크기 조정처럼 게임 규칙이나 UI 배치 구조를 바꾸지 않는 그래픽 작업은 항상 그래픽 전용 브랜치에서 진행한다.
- 새 그래픽 브랜치는 최신 `origin/main`에서 만들고 `agent/graphics-<주제>-YYYYMMDD` 형식으로 이름을 정한다. 데이터 테이블 또는 다른 기능 브랜치에서 분기하지 않는다.
- 그래픽 브랜치에는 이미지·벡터 에셋, Godot 임포트 메타데이터, 불가피한 리소스 경로 참조 수정, 출처·라이선스 기록만 포함한다.
- 게임 규칙, 데이터 테이블, UI 위치·구성, 일반 기능, 무관한 리팩터링과 Web 빌드 결과물은 그래픽 브랜치에 커밋하지 않는다.
- 기능이나 UI 구조 변경이 함께 필요하면 최신 `main`에서 별도의 목적별 브랜치를 만든다.
- 그래픽 작업 도중 다른 유형의 명령이 들어오면 그래픽 변경을 전용 브랜치에 안전하게 보존한 뒤 최신 `main`에서 별도 브랜치를 만들어 작업한다.
- 그래픽 브랜치는 사용자의 명시적인 병합 또는 배포 지시 전에는 `main`에 자동 병합하지 않는다.

## 승인과 검증

- 완성 이미지를 사용자에게 먼저 공유하고 실제 프로젝트 적용 승인을 받은 뒤 반영한다.
- 승인된 시안 범위의 변형 생성과 검토는 반복 승인받지 않지만, 최종 적용 승인은 유지한다.
- 외부 에셋은 출처, 제작자, URL, 라이선스와 사용 범위를 즉시 기록한다.
- 확인용 임시 Web 빌드는 만들 수 있지만 `build/web/` 결과물은 그래픽 전용 커밋에 포함하지 않는다.
- 코드·데이터·입력 동작을 바꾸지 않는 단순 이미지 작업은 에셋 임포트, 장면 파싱, Web 표시처럼 중요도가 높은 검증만 수행하고 관련 없는 전체 회귀 테스트는 생략한다.
- `main` 반영 전 최신 `origin/main` 기준 충돌 여부와 에셋 참조·임포트 상태를 확인한다.
