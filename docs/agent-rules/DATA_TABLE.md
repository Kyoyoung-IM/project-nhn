# 데이터 테이블 작업 지침

이 문서는 기준 Google Sheets 조회, 로컬 데이터 사본 갱신, 데이터 로더 호환과 정적 무결성 검사에 적용한다.

## 원본과 데이터 구조

- 기준 데이터 테이블은 `https://docs.google.com/spreadsheets/d/1DNYhAyOK-8hTO4hKY_9cGGzvM-DoM99ttiObfkve59s/edit?usp=sharing`이다.
- 기준 데이터 테이블과 연결된 Google Sheets는 항상 읽기 전용 원본으로 취급한다. 셀, 시트, 서식, 권한과 댓글을 직접 또는 API·자동화 도구로 수정하지 않는다.
- 프로토타입에는 원본을 읽어 만든 로컬 JSON/CSV/Resource 사본만 사용한다. 런타임에 Google Sheets를 호출하지 않는다.
- 전투 수치를 스크립트에 직접 하드코딩하지 않고 교체 가능한 데이터로 분리한다.
- `Define`, `Turret`, `Monster`, `SpawnTable`, `ShopGacha`를 별도 데이터 구조로 유지한다.
- 데이터 로더는 잘못된 ID, 누락된 다음 Tier, 확률 합계와 존재하지 않는 웨이브를 검사한다. 같은 웨이브의 동일한 `spawnOrder`는 같은 생성 그룹을 뜻하므로 허용한다.
- `attackspeed`는 `N초당 1회 공격`을 의미하므로 코드에서는 `attack_interval_sec`처럼 의미가 분명한 이름으로 매핑한다.
- 원본 ID의 `spped1`, `spped2` 같은 오탈자는 사용자 확인 없이 바꾸지 않고 표시 이름과 내부 ID를 분리한다.
- 구조 검증과 밸런싱을 분리한다. 먼저 로딩·전투·머지가 동작하게 한 뒤 플레이테스트로 수치를 조정한다.

## 데이터 전용 브랜치

- 최신 내용을 로컬 프로젝트에 반영할 때는 항상 데이터 전용 브랜치를 먼저 생성하거나 기존 전용 브랜치로 전환한다.
- 새 데이터 브랜치는 최신 `origin/main`에서 만들고 `agent/data-table-<주제>-YYYYMMDD` 형식으로 이름을 정한다. 다른 기능 브랜치에서 분기하지 않는다.
- 데이터 브랜치에는 읽기 전용 원본 조회, 로컬 사본 갱신, 필드 매핑·로더 호환, 데이터 검증 테스트와 데이터 문제로 직접 발생한 당일 `REQUEST.md`만 포함한다.
- 그래픽, UI, 연출, 일반 전투 기능, 무관한 리팩터링과 Web 빌드 결과물은 데이터 브랜치에 커밋하지 않는다.
- 다른 유형의 명령이 들어오면 데이터 변경을 전용 브랜치에 보존한 뒤 최신 `main`에서 별도 브랜치를 만들어 작업한다.
- 데이터 작업을 다시 시작할 때는 최신 `origin/main` 기준으로 갱신하고 범위 밖 변경이 섞이지 않았는지 확인한다.
- `main` 반영 전 최신 `origin/main` 기준 충돌 여부와 관련 데이터 검증을 확인한다. 충돌 시 강제 병합하거나 무관한 파일을 덮어쓰지 않는다.
- 사용자의 명시적인 병합 또는 배포 지시 전에는 `main`에 자동 병합하지 않는다.

## Design Request 일일 파일

- 요청 문서는 `Design Request/YYYYMMDD REQUEST.md` 형식으로 관리한다.
- 날짜 경계는 KST 매일 04:00이다. 04:00 이상에는 당일 파일, 미만에는 전날 파일을 활성 파일로 사용한다.
- 활성 파일이 없으면 만들고, 새 04:00 구간이 시작되면 이전 파일은 읽기 전용 이력으로 취급한다.
- 이전 이슈의 후속 내용은 현재 활성 파일에 원본 파일명과 이슈 ID를 참조해 새로 기록한다. 이전 파일을 수정하거나 자동 복사하지 않는다.
- 누락, 충돌, 이상값 또는 추가 컬럼 필요를 발견하면 이슈 내용, 기획자 요청 사항, 현재 임시 처리와 상태를 기록한다.
