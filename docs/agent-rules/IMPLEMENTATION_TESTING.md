# 구현 및 검증 지침

이 문서는 Godot 코드·장면·게임 기능 구현, 버그 수정과 관련 검증에 적용한다.

## 개발 우선순위

1. 실행 가능한 기본 게임 루프
2. 적 이동, 터렛 배치, 공격, 피격, 사망
3. 상점, 구매, 머지, 골드
4. 웨이브 진행, 승리와 패배
5. 플레이 피드백과 UI 정리
6. 데이터 검증과 밸런싱
7. Web 빌드 및 제출 안정성
8. 추가 연출과 선택 기능

- 새 기능보다 크래시, 진행 불가, 데이터 오류와 Web 실행 오류를 먼저 해결한다.
- AI 공세 디렉터는 사용자가 별도로 요청하기 전에는 구현하지 않는 후순위 선택 기능이다.
- 규칙 기반 또는 유틸리티 기반 시스템을 머신러닝이라고 표현하지 않는다.

## Godot 구현

- Godot 4와 GDScript를 사용한다.
- 프로젝트 파일은 `game/project.godot` 하나만 사용하며 별도의 프로젝트를 만들지 않는다.
- 게임 코드와 리소스 경로에는 `res://`를 사용하고 개인 PC 절대 경로를 넣지 않는다.
- Web 대상은 Compatibility 렌더러와 단일 스레드 내보내기를 기본으로 한다.
- Web에서 검증되지 않은 GDExtension은 사용하지 않는다.
- 첫 화면에는 사용자 클릭을 받는 시작 버튼을 두어 브라우저 오디오 제한에 대응한다.
- 고정 RNG 시드 또는 디버그 시드를 제공해 버그와 영상 장면을 재현할 수 있게 한다.
- 실제 플랫포머 물리나 탐색 AI처럼 기획에 없는 복잡한 시스템을 임의로 추가하지 않는다.

## 작업과 완료 기준

- 짧은 기능 단위로 구현하고 항상 플레이 가능한 상태를 유지한다.
- 변경 전 관련 장면과 스크립트를 읽고 기존 사용자 작업을 확인한다.
- 기능 구현에 꼭 필요하지 않은 대규모 리팩터링을 피한다.
- 변경 후 관련 장면을 실행하고 가능한 범위에서 Web 빌드로 확인한다.
- 관련 기능의 정상 경로와 대표 실패 경로를 확인한다.
- 오류 없이 장면을 실행할 수 있어야 한다.
- 플레이어에게 필요한 상태와 결과 피드백을 표시한다.
- 임시 절대 경로, 비밀 키와 개인 자격 증명을 남기지 않는다.
- 이해하지 못한 생성 코드를 그대로 제출하지 않는다.
- 기능 또는 게임 규칙이 바뀌면 관련 데이터와 `DESIGN.md`, `docs/GAME_SPEC.md`를 함께 갱신한다.
- 테스트 범위는 변경 위험에 비례시킨다. 유형별 지침이 더 좁은 테스트 범위를 지정하면 그 범위를 따른다.
